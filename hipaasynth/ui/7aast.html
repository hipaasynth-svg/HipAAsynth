HipAAsynth · 7AAST model stress test

Check whether a clinical AI model catches the condition it is meant to catch, on synthetic patients built to include the people real data leaves out. Everything runs on this computer. Synthetic cohort generator

1What does the model do?

This decides which cases the model is shown and how its answers are read.

2Which model?

These answer for you, so "What it answers" is set for them. A published score is run for the condition it was made for.

The model reads each case and must end with FINAL_ANSWER: yes or no; temperature is 0. A full run makes about 13 calls per patient (fewer if you turn checks off below), billed to your key.

  1. Download the cases. You get cases.jsonl (one case per line) and cases_answers.csv (a case_id and an empty answer column).
  2. Run every case through your model the way you normally do (inside the EHR, a batch job, a vendor portal) and write its answer next to the case id. Yes or no answers can be yes/no, true/false or 1/0; scores are numbers; a blank answer means the model declined.
  3. Upload the filled-in answers file (.csv or .jsonl).

Keep the settings below the same for downloading and running, or the cases will not match.

More settings

3Which checks?

Accuracy always runs. Turning a check off saves model calls, but the report then says it is a partial run and a PASS covers only the checks shown.

4Who is testing

Locked into the report and covered by its hash. The date and time are recorded by the tool when the run starts and ends, so they cannot be typed in or changed later.

Signing and Bitcoin timestamps are made by the local tool (hipaasynth ui).
